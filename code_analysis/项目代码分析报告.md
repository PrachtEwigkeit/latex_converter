# ChatGPT LaTeX Cleaner 项目代码分析报告

> 分析日期：2026-06-27  
> 分析范围：当前工作区中的 Windows 与 Ubuntu 两个版本

## 1. 项目目标

该项目用于清洗从 ChatGPT 网页端复制出来的文本，将复制过程中损坏或不适合 Markdown 渲染的公式转换为 Markdown + LaTeX 格式。

项目提供三种使用方式：

1. Streamlit 网页界面：手动粘贴并转换。
2. 一键使用：读取剪贴板、转换、再把结果写回剪贴板。
3. 命令行：读取文件、标准输入或剪贴板，并输出到文件、终端或剪贴板。

各文件职责如下：

| `app.py` | Streamlit 前端、页面状态和按钮交互 |

Windows 和 Ubuntu 的前端及清洗算法基本相同。主要平台差异是剪贴板访问和启动方式。

## 3. 总体架构

```text
用户输入或剪贴板
        |
        v
Streamlit app.py / 命令行 main()
        |
        v
convert_text()
        |
        +--> 文本规范化
        +--> 保护代码、链接和已有公式
        +--> 转换独立中括号块
        +--> 保护新生成的块公式
        +--> 判断并转换行内公式
        +--> 恢复受保护内容
        |
        v
转换结果 + Stats 统计
        |
        +--> 页面右栏
        +--> 下载文件
        +--> 系统剪贴板
        +--> 命令行输出
```

前端不直接实现清洗规则。所有入口最终都调用 `convert_text()`，因此网页操作和命令行操作使用同一套转换逻辑。

## 4. Streamlit 前端如何工作

### 4.1 页面组成

两个版本的 `app.py` 都包含：

- 侧边栏转换设置。
- “一键使用”“转换”“清空”三个按钮。
- 左侧原始文本框。
- 右侧转换结果文本框。
- 结果和转换报告下载按钮。
- 可选的转换报告显示区域。

### 4.2 Session State

Streamlit 每次交互都会重新执行脚本，因此程序使用 `st.session_state` 保存：

| 状态 | 内容 |
| --- | --- |
| `raw_text` | 当前原始文本 |
| `raw_text_input` | 左侧文本框内容 |
| `converted_text` | 当前转换结果 |
| `converted_text_area` | 右侧文本框内容 |
| `report_text` | 转换统计报告 |
| `status_message` | 操作结果提示 |
| `status_kind` | 提示类型 |

`run_conversion()` 是前端的统一转换入口。它读取侧边栏设置，调用核心模块的 `convert_text()`，然后更新左右文本框及报告。

### 4.3 一键使用流程

点击“一键使用”后执行以下步骤：

```text
read_clipboard()
        |
        v
run_conversion()
        |
        v
write_clipboard()
        |
        v
再次 read_clipboard() 校验写入结果
```

如果写回后读取到的内容与转换结果完全相同，页面显示成功；否则显示警告，并保留右侧转换结果供手动复制。

“转换”按钮只处理左侧文本，不操作剪贴板。“清空”按钮会清理文本框、报告和状态消息。

## 5. 核心转换流水线

核心入口是两个版本 `chatgpt_latex_cleaner.py` 中的 `convert_text()`。

### 5.1 文本规范化

`normalize_text()` 完成两件事：

1. 将 Windows 的 `\r\n` 和旧式 `\r` 换行统一为 `\n`。
2. 删除每一行末尾的空格和制表符。

统一换行后，后续按行识别公式的规则可以在 Windows 和 Ubuntu 上得到一致结果。

### 5.2 保护敏感区域

`protect_sensitive_regions()` 使用 `PlaceholderManager` 把不应参与普通规则匹配的内容替换为唯一占位符。

被保护的内容包括：

- Markdown 围栏代码块。
- 已存在的 `$$...$$` 块公式。
- 已存在的 `$...$` 行内公式。
- Markdown 行内代码。
- Markdown 链接和引用链接。
- 原始 URL。

例如：

```text
`(q)` -> @@__CGPT_LATEX_INLINE_CODE_0__@@
```

所有转换完成后，`PlaceholderManager.restore()` 再按相反顺序恢复原文。这种设计避免了代码、链接中的括号和符号被当作公式。

已有 LaTeX 公式在被保护前仍会执行内部修复，但不会再次参与块公式或行内公式转换。

### 5.3 独立中括号块转换

`convert_display_math_blocks()` 按行扫描文本。

只要 `[` 和 `]` 分别独占一行并且能够闭合，中间内容就统一转换为 `$$...$$`：

```text
[
0000
]
```

转换为：

```text
$$
0000
$$
```

该规则不再猜测内部内容是否“像公式”，因此纯数字内容也会转换。未找到闭合 `]` 时，原文保持不变，并增加 `skipped_unclosed_display_blocks` 统计。

### 5.4 保护新生成的块公式

中括号块转换完成后，`protect_display_math_after_conversion()` 会立即保护新生成的 `$$...$$`。

这样做是为了防止块公式内部的 `(q)`、`H(s)` 等内容在下一阶段被错误转换成行内 `$...$`。

### 5.5 行内公式判断

`convert_inline_math_parentheses()` 扫描普通圆括号，并使用 `find_matching_paren()` 支持嵌套括号。

括号内容交给 `decide_math_like()` 判断。主要规则如下：

| 内容特征 | 处理 |
| --- | --- |
| LaTeX 命令，如 `\frac` | 高置信度转换 |
| 含 `=<>^_` 等数学符号 | 高置信度转换 |
| 函数形式，如 `f(q)` | 转换 |
| 下标或上标，如 `q_i` | 转换 |
| 数学空间，如 `SE3`、`R3` | 转换 |
| 单字母，如 `q` | 默认转换，严格模式不转换 |
| 纯数字、URL、邮箱、中文普通语句 | 不转换 |

例如：

```text
(f(q)=y) -> $f(q)=y$
```

低于 `0.70` 置信度的转换会被记录到 `low_confidence_inline`，方便用户通过转换报告人工检查。

## 6. 公式内部修复

`repair_formula()` 和 `repair_latex_syntax()` 负责修复已经确定属于公式的内容。

### 6.1 下标损坏

修复网页复制时可能出现的星号替代下标问题：

```text
{q_i}*{i=1}^N -> {q_i}_{i=1}^N
\mathcal M*{y^*} -> \mathcal M_{y^*}
```

### 6.2 特殊字符和定界符

包括：

```text
J(q)^# -> J(q)^{\#}
\left{...\right} -> \left\{...\right\}
```

裸露的 `#` 也会被转义，避免 KaTeX 或 LaTeX 将其当作宏参数符号。

### 6.3 中文与公式混排

`repair_math_text_segments()` 扫描数学模式中裸露的中文和中文标点，并重新包入 `\text{...}`。

例如：

```text
H(s)，不是直接给 }H(s)。
```

修复为：

```text
H(s)\text{，不是直接给 }H(s)\text{。}
```

扫描器会跳过已经正确闭合的 `\text{...}`，并在满足条件时删除复制过程中残留的多余 `}`。

### 6.4 多行数学环境的行分隔符

`repair_multiline_math_row_breaks()` 处理以下环境：

- `array`
- `aligned`、`alignedat`
- `gathered`、`split`、`cases`
- 各类 `matrix`

在这些环境内部，行尾错误的单个 `\` 会被修复为 `\\`。已有的 `\\`、`\hline` 以及环境外的反斜杠不会被修改。

### 6.5 连续等号或减号伪影

ChatGPT 网页复制可能将公式中的运算符变成 Markdown 标题线：

```text
\dot{\xi}
=========
# \hat f(\xi)
```

`repair_copied_display_math_lines()` 会识别由连续 `=` 或 `-` 组成的行，去除可能出现的 Markdown `#`，并将相邻公式重新连接。

## 7. 转换统计

`Stats` 数据类在一次转换过程中累计：

- 块公式转换数量。
- 行内公式转换数量。
- 公式内部修复数量。
- 连续等号或减号伪影修复数量。
- 中文文本修复数量。
- 多行公式行分隔符修复数量。
- 未闭合块公式数量。
- 各类受保护区域数量。
- 低置信度行内公式记录。

`format_report()` 将这些数据转换为可读文本。前端可以显示或下载该报告，命令行默认将报告输出到标准错误流。

## 8. 剪贴板实现

### 8.1 Windows

Windows 版本优先通过 PowerShell 调用：

- `Get-Clipboard -Raw`
- `Set-Clipboard`

Python 和 PowerShell 之间使用 Base64 传递 UTF-8 文本。这样可以避免中文、换行、引号、反斜杠和 LaTeX 内容被命令行转义破坏。

PowerShell 不可用时，程序依次尝试：

1. `pyperclip`
2. `tkinter`

### 8.2 Ubuntu

Ubuntu 版本优先根据系统中存在的工具尝试：

| 桌面环境 | 读取 | 写入 |
| --- | --- | --- |
| Wayland | `wl-paste` | `wl-copy` |
| X11 | `xclip` 或 `xsel` | `xclip` 或 `xsel` |

这些命令不可用或执行失败时，再尝试 `pyperclip` 和 `tkinter`。

剪贴板操作依赖图形桌面会话。在纯 SSH、无桌面或权限隔离环境中，即使程序本身正常运行，也可能无法访问当前用户的系统剪贴板。

## 9. 启动脚本

### 9.1 Windows 批处理

`start_latex_cleaner.bat` 首先切换到脚本所在目录，避免用户从其他目录启动时找不到 `app.py`。

Python 查找顺序为：

1. `windows_version/.venv/Scripts/python.exe`
2. `D:\ANACONDA\python.exe`
3. `PATH` 中的 `python.exe`

脚本还会：

- 检查 `app.py` 是否存在。
- 检查当前 Python 是否安装 Streamlit。
- 从 `8501` 开始寻找空闲端口。
- 延迟打开浏览器。
- 使用选定的 Python 启动 Streamlit。
- 支持 `--dry-run` 进行启动前检查。

### 9.2 Ubuntu 安装与启动

`install_ubuntu.sh`：

1. 查找 Python 3.8 或更高版本。
2. 创建 `ubuntu_version/.venv`。
3. 升级 `pip`。
4. 安装 `requirements.txt`。

`start_latex_cleaner.sh`：

- 优先使用 `.venv`。
- 支持 `--install` 自动安装依赖。
- 支持 `--dry-run`、`--no-browser` 和 `--port`。
- 从指定端口开始寻找空闲端口。
- 使用 `xdg-open` 打开浏览器。
- 启动 Streamlit 服务。

## 10. 命令行入口

直接运行 `chatgpt_latex_cleaner.py` 时会进入 `main()`。

主要参数：

| 参数 | 作用 |
| --- | --- |
| `input` | 输入文本文件；省略时读取标准输入 |
| `-o, --output` | 输出到指定 Markdown 文件 |
| `--from-clipboard` | 从剪贴板读取 |
| `--to-clipboard` | 将结果写回剪贴板 |
| `--strict` | 不转换单字母圆括号 |
| `--no-repair` | 关闭公式内部修复 |
| `--no-report` | 不输出转换报告 |

示例：

```bash
python chatgpt_latex_cleaner.py input.txt -o output.md
python chatgpt_latex_cleaner.py --from-clipboard --to-clipboard
```

## 11. 依赖关系

两个版本的 Python 依赖为：

- Windows：`streamlit`，用于网页界面。
- Ubuntu：`streamlit` 和 `pyperclip`；后者作为跨平台剪贴板兜底。

其他功能主要使用 Python 标准库，包括 `re`、`subprocess`、`argparse`、`base64`、`dataclasses` 和 `pathlib`。

Ubuntu 的 `wl-clipboard`、`xclip`、`xsel` 属于可选系统依赖，不通过 `pip` 安装。

## 12. 当前设计的优点

1. 所有入口复用 `convert_text()`，核心行为集中。
2. 先保护敏感区域，再转换普通文本，降低误处理风险。
3. 转换与统计同时完成，便于发现低置信度结果。
4. 剪贴板实现有多级回退机制。
5. Windows 使用 Base64 跨进程传输，能够稳定处理复杂 LaTeX 和中文。
6. 大部分规则具有幂等性，重复清洗通常不会继续改变结果。

## 13. 风险和维护建议

### 13.1 两份核心代码需要同步维护

Windows 和 Ubuntu 目录中各自保存了一份 `app.py` 和 `chatgpt_latex_cleaner.py`。当前清洗规则一致，但每次增加规则都必须同时修改两个文件。

长期建议将平台无关的清洗算法提取到根目录共享模块，仅把剪贴板适配器和启动脚本留在各平台目录中。

### 13.2 规则属于启发式处理

行内公式判断和损坏修复主要依赖正则表达式及字符扫描，并不是完整 LaTeX 解析器。复杂嵌套宏、自定义命令或异常括号仍可能出现误判。

新增清洗规则时应尽量限定上下文，例如只在数学环境、特定行结构或明确命令附近处理，避免全局替换。

### 13.3 缺少项目内自动化测试

当前工作区没有持久化的测试目录。后续建议为以下内容建立参数化测试：

- 独立中括号块。
- 行内公式置信度判断。
- 中文与公式混排。
- `array` 等环境的行尾反斜杠。
- 连续等号和减号伪影。
- 代码块、链接和已有公式保护。
- Windows 与 Ubuntu 核心转换结果一致性。

### 13.4 剪贴板依赖运行环境

浏览器页面由 Streamlit 服务提供，但剪贴板实际由运行 Python 的系统进程访问。远程服务器、容器、SSH 或不同桌面用户会话可能无法访问用户当前桌面的剪贴板。

### 13.5 统计字段命名可进一步细化

`subscript_repairs` 当前不仅可能统计下标修复，还可能因为其他公式语法变化而增加。若后续需要精确分析，可以为每类修复建立独立字段。

## 14. 修改或新增规则时的推荐流程

1. 先确认错误发生在块公式、行内公式还是普通文本。
2. 优先在现有专用修复函数中扩展，不做无上下文的全局替换。
3. 同步修改 Windows 和 Ubuntu 两份核心文件。
4. 使用错误样例验证修复结果。
5. 使用正确样例验证不会被重复或错误修改。
6. 对转换结果再次执行转换，检查规则是否幂等。
7. 编译检查两个版本，并确认转换报告计数正确。

## 15. 总结

该项目采用“前端交互层 + 核心文本转换层 + 平台剪贴板适配层”的结构。

核心思路不是完整解析 LaTeX，而是针对 ChatGPT 网页复制产生的常见格式损坏，按照明确上下文进行保护、识别和修复。`PlaceholderManager` 负责避免误伤，`convert_text()` 负责组织流水线，各类专用修复函数负责处理具体损坏模式，`Stats` 则提供可追踪的转换结果。

对于当前规模，这种实现直接且易于扩展。后续最值得优先改进的是提取两个平台共用的核心模块，并建立自动化回归测试，降低双份代码同步维护的风险。
